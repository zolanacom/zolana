# User-paid native withdrawal fees

The native protocol's historical `sponsor` field is a fee-payer authority, not a privileged operator identity. A user can already sign that role. Derive a separate Ed25519 fee authority from the encrypted wallet seed, with a distinct hash domain and the same network/genesis separation as the public withdrawal authority. Keep the two accounts distinct so the existing recipient-bound authorization, validator checks, historical proofs and feature activation remain unchanged. No consensus upgrade is needed for this wallet feature on a network that already enables recipient-bound withdrawals.

`withdraw --fee-payer user --max-fee-debit <units>` signs initialization, uploads, finalization and cleanup with that recovered fee key. It refuses all operator-sponsor options and never opens the sponsor vault or policy. Existing sponsored payments and their original-reservation recovery remain supported. General user-paid deposits/sends are outside this first path.

The fee account needs public native coins in advance. It cannot pay the first transaction out of still-shielded funds. The current fixed proof buffer also needs substantial temporary rent, which is refunded when closed. A read-only quote reports the fee address, actual balance, refundable staging rent, permanent storage rent, transaction fees, gross-debit ceiling, a separate cleanup reserve, minimum remaining account balance and funding shortfall. Denomination, rent parameters and initial test-coin distribution remain development settings. This is neither zero-gas onboarding nor a Solana-mainnet funding path.

The user's explicit debit ceiling is persisted inside the original owner-only staging record, together with payer/network and initialization identity, before any broadcast. Every potential transaction fee, initialization rent and finalization storage debit is charged durably before broadcast. Refunds or uncertain execution never reset the charged amount. Normal transactions cannot consume the reserved cleanup allowance. Recovery derives the original fee key from the encrypted seed and reuses the original cap; it rejects operator options, wrong keys and changed limits. No extra fee-policy file or detached budget journal needs coordinated recovery.

Pending finalization still precedes broadcast. Resolve uses canonical full RPC history, reports the authorized recipient and payer and never repeats a withdrawal. The staging record and charged cap survive wallet and validator crashes. Preserve them until acceptance and rent cleanup are established. A restored seed recovers the same fee signing authority, but does not replace an unresolved operation's journal. Keep one active wallet operation per seed; independently restored copies are not a shared durable operation lock.

The local wallet can run without sponsor credentials. It disables sponsor-only faucet/send actions, shows the user-funded withdrawal quote and requires review of the gross-debit bound. There is no automatic sponsor fallback. The acceptance utility grants valueless initial gas from the local cold treasury once; it is test setup, not a production faucet. Production onboarding needs an explicit gas distribution/top-up path. Larger fee changes can exhaust the original allowance; recovery fails closed rather than silently increasing consent.

The fee account, its funding source, fees and timing are public. Reusing it links those public operations; this does not provide network anonymity or hide public withdrawal values.

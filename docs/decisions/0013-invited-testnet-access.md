# Invited testnet access and persistent abuse budgets

Tester admission applies to the wallet RPC gateway and faucet. It does not add a consensus rule or alter native payment authorization. Validator RPC/gossip remain operator-loopback. An operator who exposes raw RPC outside that boundary bypasses gateway admission. This is a local rehearsal, not a deployed permissioned network.

A new faucet is explicitly switched into invitation mode before accepting any claim. Its existing claim ledger receives a permanent marker; a separate owner-only admission ledger stores policy, hashed invitations, immutable member claims, revocations and quota counters. Missing admission state after that marker fails closed. Existing faucet roots, profiles and budgets are never silently converted or reset.

Operator-issued codes contain 256 random bits, expire after at most seven days, and are exported once to a new owner-only file. The server stores only code hashes. An optional prebound fee authority prevents first-use forwarding to another wallet. Otherwise a code is a bearer credential until first redemption. One code admits one seed-derived fee authority for seven days and binds its original signed private-address/gas-address claim. Restoring that seed recovers the same membership and grant without the code. Expiry, revocation, restore and re-encryption never refund lifetime invitation or grant capacity. Invitations deter arbitrary seed farming; they cannot prove one human per wallet or prevent voluntary sharing of an unused bearer invitation.

Admission and faucet reservations share one OS lock. The durable redemption precedes reservation; a crash between those commits is recovered by the same member's retry without another invitation. Native grant workers continue their original capped, journaled obligations after revocation: a revoked gateway session cannot cancel or duplicate an already accepted on-chain transfer. No code or access proof grants native spending authority.

Wallets sign network-, audience- and purpose-bound access proofs with their seed-derived fee authority. Join proofs also bind the exact claim and code. RPC proofs are ten-minute reusable session credentials, charged on every request; they are not per-request anti-replay signatures. A captured session credential remains usable until expiry or revocation within the same wallet quota. Remote endpoints require HTTPS. Each CLI invocation signs fresh proofs; seeds/passwords remain local, and invitation input uses an owner-only temporary file instead of command-line arguments or URLs.

The durable policy bounds lifetime invitations (at most the original 1–100 faucet slots), daily new admissions and RPC requests per member per minute (1–10,000, rehearsal 2,000). Additional fixed quotas are 30 faucet operations per member/minute, 120 signed faucet operations globally/minute and 6,000 authenticated RPC requests globally/minute. Before signature parsing, ingress charges actual socket IP and global minute buckets: faucet 240/IP and 480/global; RPC 3,000/IP and 6,000/global. Forwarded-IP headers are ignored. At most 512 current-minute ingress identities are retained. One NAT can share a limit. Time uses a persisted high-water mark; rollback beyond 30 seconds fails closed. Limits replenish at UTC minute/day boundaries, never simply on restart. Local operator write access to these policy files remains trusted.

Both services bind loopback, bound bodies and concurrency, reject browser origins and incorrect authorities, suppress request/access logging and disable proxy discovery and redirects. RPC accepts a fixed wallet method allowlist, single bounded envelopes and bounded replies. Only the genesis handshake is public; pool/history access and transaction submission require active admission. Private addresses and fee addresses are associated in operator admission/faucet records; public gas transfers and RPC/network metadata remain visible. There is no assertion of anonymity, distributed denial-of-service resistance or independent security review.

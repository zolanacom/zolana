# 0010: Device-local tester bundle with an explicit public connection profile

Status: implemented locally; external hosting and distribution remain unapproved

The wallet previously required a repository checkout and a `.data` fixture containing validator and operator configuration. Invited testers need a device-local client independent of those files. Hosting the existing password-decrypting backend as a shared website would give that host custody of users' secrets, so the backend continues to bind to `127.0.0.1` on each tester's machine.

A strict `native-wallet-profile-v1` configuration pins the chain domain, genesis fingerprint, program/pool/format, withdrawal support, display label and one RPC endpoint. `key_mode: user-wallet-v1` selects client-only behavior. Unknown fields, duplicate fields, incompatible identities and mixed operator modes fail closed. No discovery service, API-supplied RPC override or transparent failover is added. Existing disposable and guarded rehearsal modes retain their original interface.

The loopback transport accepts only `http://127.0.0.1:<nonzero-port>`. Explicit remote transport requires HTTPS with ordinary Rustls certificate validation. Credentials, query strings, fragments, whitespace and ambiguous authority forms are rejected; credentials must not enter shared configuration or logs. Redirects and implicit proxies are disabled for both modes. Genesis mismatch fails before note scanning or signing. A seed-free `check` command additionally validates the native pool owner/domain/backing and withdrawal feature activation. This remains trust in the selected RPC/validator consensus, not a light client or proof of full chain execution.

The bundle contains a host-platform wallet binary, three static UI files, two Python runtime modules, public profile, integrity manifest and upstream/dependency notices. The deterministic tar/gzip encoder fixes ordering, ownership and timestamps for identical input bytes. The builder ensures the default binary is freshly built offline; this does not promise reproducible compiler output across machines. The manifest records binary hashes, source commit and dirty state. A custom binary is an explicit builder override and is not source-proven. Hashes detect accidental changes; publisher authenticity requires a separate trusted channel/signing policy.

The launcher verifies the full file inventory before execution. Encrypted wallet/recovery/checkpoint files and pending/staging journals live in a separate owner-only application-data directory, bound to the original exact public profile. Package replacement cannot silently select another profile or overwrite that state. An endpoint change currently requires deliberate profile/data migration; automatic migration is deferred. Existing network-bound recovery envelopes are unchanged.

There are no operator keys or sponsor policy/reservations in tester mode. The initial scope supported receiving, seed recovery, balance verification and user-paid withdrawals, with private sends deferred. [Decision 0011](0011-user-paid-private-sends.md) subsequently enables explicitly user-paid private sends with the same durable authorization. Initial private test balances and public fee gas must still be provisioned separately; new deposits and operator sponsorship remain unavailable in client-only mode. The wallet's service is never opened to the LAN.

This is an unsigned local development archive. The current host is Apple Silicon macOS with Python 3.10+ required. Other platform binaries, installer/notarization, release path remapping, independently verified distribution, hosted validators/RPC, public gas distribution, retained-history operations and physical phone/Safari acceptance remain release work. Development binaries can contain local compiler/source paths; the archive is not cleared for external distribution. Upstream attribution remains intact.

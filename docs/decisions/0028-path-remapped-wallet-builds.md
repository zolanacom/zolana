# Build and inspect isolated path-remapped wallet candidates

The authenticated release workflow can approve exact download bytes, but the old debug executable contains local build paths. Prepare a distinct optimized development candidate with path remapping and byte-level inspection before signing. Do not replace the original debug executable, modify native payments or remove upstream authorship/notices.

Snapshot the allowlisted native workspace inputs into a new private build root and record a deterministic content digest. Include tracked and nonignored native source inputs, lockfile, pinned toolchain and workspace profile. Keep `.data`, `.local`, `.git`, Cargo caches and existing targets out of the snapshot. Preserve safe relative upstream symlinks, including dangling documentation links; reject absolute/escaping links or links importing existing files outside the source inventory. Recheck snapshot content before native tests and current source identity before packaging.

Use Rust 1.92.0's pinned Apple-arm64 toolchain, the existing dependency cache and a new target directory. Force locked offline Cargo, one build job and codegen unit, low process priority, no incremental artifacts/debug symbols and no linker UUID. Set encoded Rust path-prefix remaps and shell-escaped C/C++ file/debug remaps for source, build, Cargo, compiler, temporary and home roots. The recipe controls its build environment rather than inheriting arbitrary flags/wrappers. This initial recipe is native Apple-arm64 only; it is not a general cross-platform builder.

Verify actual Rust `file!`/panic and native C `__FILE__` probes before compiling the wallet. Inspect the finished executable for configured roots and generic personal/temporary prefixes in UTF-8/UTF-16, then inspect Mach-O dependencies, rpaths, debug segments, UUID and the toolchain's ad-hoc signature. An unexpected path/dependency/signature fails before exporting an approved candidate. The ad-hoc signature is not an Apple Developer identity or notarization.

Emit a path-free `BUILD.json` receipt binding the actual binary, source/lockfile digests, compiler commit, target/profile, bounded recipe, probes and inspection results. Packaging with `--build-receipt` verifies its schema, binary and current native inputs before running the local candidate's public-profile parser. Preserve that receipt inside the signed inventory and label the archive `path-remapped-development`. The independent verifier rejects absent/mismatched receipts and rechecks binary generic path prefixes. Legacy `local-development` bundles remain supported without claiming remapping. A receipt is publisher-reviewed metadata, not a cryptographic proof of a trustworthy compiler or audited source.

Run the wallet/payment library checks using the same optimized snapshot/profile. Build in a second, differently named source/output location, including spaces, and compare actual artifacts before making any reproducibility statement. Repeat signed-package crash/restore acceptance with new rehearsal keys/wallets; never read or reset original wallets or payment state. Local builds and repeat archives do not establish cross-host/toolchain reproducibility, anonymity, production security, Apple Developer signing, notarization or hosted availability. Those remain separate work.

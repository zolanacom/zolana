# Canonical archival RPC for historical pending outcomes

An encrypted scan checkpoint or retained ciphertext mirror can reconstruct private state without proving whether a particular outer transaction succeeded, failed, or never executed. A snapshot-only primary therefore cannot safely clear every old pending payment.

The gateway exposes `getWalletCanonicalHistory([after_slot, target_slot, anchor_or_null])` as a separate invited read. The operator fixes the archive endpoint at startup; callers cannot choose a URL, credentials, methods, finality or encoding. The endpoint is disabled unless configured. Existing canonical RPC methods retain their primary-validator semantics. A missing configured archive is an error; it is never replaced with retained metadata.

Each page has at most 16 full finalized blocks, an 8 MiB per-block bound, a 16 MiB envelope bound and a shared 15-second upstream deadline. The gateway verifies the archive genesis, compares the primary and archive finalized target hash/height and pins that anchor across continuations. It fetches bounded produced-slot lists with `getBlocksWithLimit` and full base64 transaction bodies. No archive cursor session lives in the gateway, so a captured cursor survives its restart. All pages use the existing invitation proof, revocation, durable ingress and per-member RPC quotas.

For an otherwise ambiguous pending outcome, the wallet replays full canonical history from genesis, verifying native transaction signatures, instruction/proof effects, block continuity, the final primary header and complete pool reconciliation. It rejects missing/reordered/substituted blocks, changed anchors and incomplete transaction bodies. Canonical finalizations bind the original signature and staging account; withdrawals also match the saved recipient, amount and sponsor. Canonical failed finalizations verify their signatures before supplying a failed outcome. Absence clears a journal only after complete canonical coverage and finalized block height past the saved validity height. Resolution is read-only apart from local cache/outcome files and never signs or broadcasts another payment. Original staging rent is reclaimed separately.

This is the same trusted operator RPC model as direct canonical scanning, **not** an independent light-client proof of transaction inclusion or non-inclusion. Block hashes alone do not authenticate RPC execution metadata. The operator must preserve and monitor a real full-history validator. A compact mirror cannot replace it. The installed local topology pins the archive lane to its existing full-history primary via the same private Unix transport; that is not a second archival replica or host-loss protection. The separate snapshot-primary/full-history-archive acceptance fixture exercises the pruned-primary case.

The sealed service inventory becomes v5, retaining explicit v1–v4 inventories for paused-state upgrades and rollback. The normal service and wallet profile keep their existing identity and private data. Test-only service actions use a distinct finite LOCAL-028 session and leave the normal job unloaded afterward. Nothing is hosted or pushed.

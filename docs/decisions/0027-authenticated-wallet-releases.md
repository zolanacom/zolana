# Authenticate standalone downloads before executing them

A checksum manifest inside a wallet archive detects damage but cannot establish the publisher. Prepare a separately trusted offline verifier and signed release descriptor. The verifier and publisher pin must arrive through an independently authenticated channel; copying either beside an untrusted archive does not establish trust.

Use OpenSSL/LibreSSL's standard ECDSA P-256/SHA-256 implementation, with canonical named-curve SubjectPublicKeyInfo DER as the public-key identity. Hash that DER for the independently pinned publisher fingerprint. Sign a domain-separated canonical descriptor binding the compressed archive digest/size, bundle manifest digest, exact public-profile digest, platform, release channel, monotonic sequence, source commit and development-build kind. Do not implement elliptic-curve arithmetic or trust a public key selected by the download. This first workflow deliberately accepts only `local-development` bundles; it is not Apple signing/notarization or production-release approval.

The trusted verifier runs outside the replaceable wallet archive and never imports or executes downloaded Python/native code during verification or installation. After signature/policy and whole-archive validation, parse a bounded archive manually. Refuse links, traversal, duplicate/conflicting names, special files, modes outside the package policy, unallowlisted files and mismatched inventory/hashes. The exact public profile is an independent pin: a valid publisher signature alone cannot silently redirect an installed wallet to another network/endpoint.

Initialize one new private installation root with the reviewed key, profile, channel and independently known minimum acceptable sequence. Persist the accepted high-water mark and reject older releases or different bytes at the same sequence. This requires intact trusted local state; it is not hardware-backed rollback resistance, a revocation service or proof that an offline client knows the latest release. Key/network/channel migration and recovery of lost trust state require separate review.

Plan an update durably, write a new private version directory, fsync files/directories, rename the complete version and activate it through one atomic state-pointer replacement. Interrupted updates resume only the same original signed action. Partial staging directories remain as evidence. A version already published is reverified rather than overwritten. Uncertain storage commits poison the running installer until it reopens the persisted state. Never reset initialized state to bypass an interrupted update.

All wallet/recovery/cache/pending/staging files remain in their separate existing data directory. The installer does not read or migrate them. The trusted runner checks the installed descriptor/signature/inventory before every launch, uses isolated Python and holds an exclusive installation lock. The wallet inherits that lock so killing its parent runner cannot permit an update underneath the live wallet. Stop the wallet before updating; external data paths must not overlap the installation root.

Local acceptance uses a fresh throwaway rehearsal publisher and new encrypted wallets only. Actual production key custody, independently distributed verifier/pins, path-remapped reviewed builds, Apple Developer signing/notarization, supported-platform acceptance and real hosted services remain launch work. This feature authenticates the approved bytes; it does not audit their cryptography or prove reproducible native compilation.

# Prepare independent observation and receipt-based remote delivery

The local observer cannot detect loss of its own machine. Its stdout acknowledgement also cannot establish storage on another machine. Prepare three separately runnable, unprivileged roles: a read-only source-host exporter, an off-host observer with its own journal, and a durable HTTPS alert inbox. Actual host placement and any human paging integration remain explicit deployment choices.

The exporter accepts one fixed health route and whitelisted request schema. It reads only the sanitized heartbeat and the fixed launchd job. The observer pins a deployment identity, exact HTTPS origins, CA digests and distinct health-read/alert-write capabilities. Each health response must echo a fresh random challenge with a bounded source timestamp. This detects stale/cached responses without adding wallet or RPC capabilities. A source/exporter outage alerts even when the last successful observation was paused. Production configuration explicitly expects a running service; an unloaded job then alerts too.

The existing incident state machine remains authoritative for fresh ready health, stale finality, grace across restart and actual recovery. A transport failure cannot reuse a cached pause or ready response. Temporary delivery failure does not stop observations; one bounded delivery attempt per cycle and exponential backoff preserve sampling. Local state corruption or failed local persistence terminates visibly rather than becoming an ordinary network retry.

Each pending journal binds to its deployment, source/alert origins, CA pins and expected-running policy. Stdout cannot acknowledge a remote-bound event. A matching receipt must confirm the same event ID, canonical content hash and literal durable boolean before delivery is persisted. The inbox atomically stores each event before replying, retains ID deduplication across restart, and rejects changed-content retries. Crashes before commit retry normally; crashes after commit before acknowledgement retry the same ID and reuse its durable receipt. An uncertain post-replace fsync poisons the receiver until restart, preventing later writes from rolling back an ambiguous commit.

The standalone package contains only fixed monitoring code, notices and examples. It includes no credentials, service binaries or private paths from the checkout. Its entry point checks the reviewed inventory and hashes before importing code. Local mode is loopback-only and finite. Explicit network mode and reviewed configuration are required for actual off-host use. No service is installed by preparation or testing.

The remote inbox is a machine-delivery destination, not proof that a human received a page. Provider-specific email/Slack/Telegram routing, supervision/watchdog, off-host availability, backup retention, TLS provisioning, release signing and independent review remain deployment requirements. Checksums and health counters do not prove consensus or defeat a compromised source host.

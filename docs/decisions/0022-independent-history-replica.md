# Replicate public recovery history independently

Validator snapshots preserve the pool and permanent nullifiers but omit old ciphertexts from closed staging accounts. The primary archive and its existing captured mirror share one host. Independent replication is needed before relying on that history for invited testers.

`history_replica.py` provides a bounded TLS receiver and sender. The receiver pins the original network/genesis and uses a dedicated `native-history-replica-key-v1` credential. This credential authorizes only retained public-history transfer: it cannot call raw RPC, sign transactions, admit testers or read arbitrary files. Replicas contain no validator keys, wallet seeds/passwords, sponsor files, admission state or operator RPC capability. Hostname and CA checks remain enabled; senders reject cleartext origins, redirects and environment proxies. Local receiver commands bind loopback and have finite lifetimes. Actual off-host placement requires a separately operated host/private transport and deployment review.

Each sender captures one exact manifest. Preparation must extend the receiver's committed immutable descriptor prefix. Only explicitly referenced checksum-addressed segment names can be uploaded. Existing names cannot be overwritten. Uploads are synced before acknowledgement; the final commit independently checks every segment's checksum, continuity, bounds and identity, then publishes and directory-syncs the manifest last. A crash can leave unreferenced immutable files; retries reuse exact bytes. The previous committed manifest survives interrupted uploads/publication. A lost commit reply can be retried against the same prefix without reuploading its committed payloads. Nothing prunes or silently repartitions a previously committed prefix.

The native collector remains responsible for proof verification and reconciliation against finalized RPC. Replica checksums/structural validation and its durable receipt are not consensus proofs. Restoring wallets replay the full native history and reconcile with a trusted current finalized pool. Replicated ciphertext metadata cannot prove historical outer-transaction inclusion or absence; old ambiguous payments still require canonical archival RPC. This does not replace validator/tower/key backups or establish power-loss durability on arbitrary storage hardware.

When an operator configures replication, `Retention.collect()` requires a receipt for the exact captured mirror manifest before reporting a new success or opening ingress. CA material and the history-only credential use fixed owner-only paths. A persistent requirement marker survives collector/service restart; deleting or damaging the policy cannot silently downgrade to local-only retention. Failure blocks health, and the existing supervisor closes ingress and pauses validators. Transfers are cancellable and bounded to 45 seconds. No callback runs arbitrary commands or accepts RPC URLs from testers.

Each receiver's incoming and committed stores have the existing 256 MiB budget and manifest/segment/record bounds. Interrupted/orphan files count toward capacity; no automatic deletion hides exhaustion. Free-space headroom is checked before ingest/commit. An OS file lock excludes a second receiver on the same root. Authenticated requests are serialized inside the existing bounded TLS server. These are monitored prototype limits, not filesystem quotas or distributed flood protection.

Local-only acceptance uses separate processes and private directories, then a real snapshot-only validator, fresh restored wallet seeds and a recovered-witness spend. The installed rehearsal uses a separate unprivileged receiver identity and preserves original private files/payment state. It restores the pre-test absence of replica configuration only after stopping the finite rehearsal, retaining all test policy/credential bytes privately for evidence. A deployed requirement marker must not be removed to work around an unavailable replica.

See [the runbook](../history-replica-runbook.md) and LOCAL-030 validation. A successful loopback rehearsal does not establish actual off-host redundancy or authorize publication.

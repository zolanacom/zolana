# Independently observe monitor and pager progress

The observer and paging adapter can fail while the validator's exported health remains readable. Their own delivery pipeline cannot reliably report its loss. Prepare a separate watchdog process, durable state and notification channel that require neither the primary alert inbox, the pager process nor PagerDuty to deliver an alert. All validation remains local against mock providers.

Publish a small owner-only progress document from each role's main loop after a completed observation/delivery cycle. A background heartbeat or fresh PID is insufficient. Expose only the exact sanitized schema through an authenticated, nonce-challenged HTTPS progress agent. The initial agent reads both roles as their shared unprivileged publishing operator; cross-UID collection and distributed role aggregation are not implemented. It needs no validator keys, raw RPC, wallet data or primary provider credential.

Persist observed instance/sequence progress and startup deadlines independently. Detect missing/invalid/stopped/stale roles, blocked delivery, overdue queues and unavailable/invalid agent observations. Repeated restarts cannot renew startup grace forever. A newly starting replacement cannot resolve an existing incident before completing work. Pin the expected primary integration fingerprint so another pager cannot accidentally establish health. Clock rollback, altered routes and damaged/missing initialized state fail visibly with evidence retained.

The watchdog owns an observation journal, local durable event inbox and notification relay. Use a separately provisioned Telegram bot/chat instead of the primary PagerDuty integration. Pin agent/provider origins, CAs, deployment, notification credential fingerprint and thresholds. Provider outages, rejection and ambiguous acceptance preserve the planned action across restart; explicit `watchdog-retry` re-arms a blocked action without sending. Do not replace queues or credentials to bypass an unresolved incident.

Telegram sendMessage does not offer an application idempotency key. Acceptance lost before local commit may duplicate a message; retain the same visible incident key and document at-least-once submission. Matching provider acceptance is never human receipt. No real bot, chat, external message or service installation is created by this work.

The reproducible v3 package contains these source roles and example configs. Actual independence requires the watchdog outside the monitor/pager host and a separately tested notification lane. Its own host/process/channel also require external liveness supervision; this package does not install an infinite chain of watchdogs. Host selection, supervision, live receipt/acknowledgement, capacity/backup policy, signing and independent review remain deployment work.

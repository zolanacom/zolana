# Separate rehearsal custody and conservative sponsorship

Keep the independent privacy L1, native proof format and NPOOL003 unchanged. Add a distinct local genesis/key ceremony rather than promoting public fixture material into a testnet identity. Treasury, payment sponsor, validator identity/voter, vote withdrawal and stake control have separate keys. Only validator identity/voter files are plaintext hot material. Authenticate encrypted recovery bundles against genesis and the public role manifest, use different cold/sponsor passwords, refuse overwrites and verify restored vote/stake authorities before exporting missing hot roles.

The managed sponsor is an operator resource, not the user's shielded spending authority or treasury. Use the existing native instruction construction and sponsor-bound authorization; do not expose arbitrary transaction signing. Reserve finite lifetime gross-debit allowances durably before preparing payments. Serialize every wallet sharing the signer with an OS lock. Persist each possible message fee/native debit before broadcasting; never refill allowances from uncertain results, process exits or staging refunds. Duplicate request IDs and wallet identity counts survive restarts and seed-file copies.

Cleanup is different from a fresh payment. Record the reservation ID in the existing staging journal. After canonical pending resolution, allow only the original wallet reservation's remaining durably uncharged allowance to close its original staging account. Do not allocate a new lifetime reservation for recovery. An exhausted new-payment policy must not itself strand recoverable rent. Original journals remain mandatory.

Reject managed-sponsor withdrawals: the current native withdrawal pays the proof's signed sponsor, so using an operator sponsor would direct the user's exit value to the operator. A user-controlled withdrawal/fee-payer flow remains a separate requirement. Native withdrawals remain implemented/tested in disposable mode; this policy restriction does not change consensus.

This first implementation is a local single-machine custody/accounting rehearsal. Its public fixture economics, tiny finite budgets and two-validator 80/20 arrangement are development settings. The browser backend still processes wallet seeds/passwords locally. Before external testnet: select parameters and validator operators, provision real offline/hardware custody, implement compromised-key rotation, public sponsor authentication/abuse controls, independent accounting/anti-rollback/replication, user-controlled exits, retention operations and independent security review. Do not publish or reuse these automated test passwords/keys. No public network is authorized.

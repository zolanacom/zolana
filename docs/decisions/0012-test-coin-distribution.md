# Self-service test coins and public gas

A standalone, backed-up wallet signs a domain-separated claim binding this network/genesis, its private receiving address and its seed-derived fee address. A pinned faucet endpoint receives only that public claim. The wallet password and recovery seed stay on the tester's device. Restoring the seed recreates the same claim.

The faucet is a separate encrypted wallet with a pre-funded private reservoir and public fee account. It has no treasury, validator, sponsor or user spending authority. Each wallet receives exactly 1,000,000 private test units and 150,000,000 public native gas units once. Gas covers the current upload-rent requirement and subsequent user-paid sends. This is distribution infrastructure for the existing privacy-native L1; consensus and payment formats do not change.

Before funding, an owner-only atomic ledger reserves one lifetime slot. The signed fee authority is unique across claims; its first private destination cannot subsequently be changed. A private receiving address is public and is not used as an admission lock, so knowing another wallet's receiving address cannot preempt that wallet's fee-authority claim. The signature proves control of the gas authority, not knowledge of an Orchard receiving key. A repeated claim returns its original state. Missing ledgers/progress fail closed, initialization refuses existing directories, and re-encrypting/restoring a key does not recreate capacity. The configured lifetime capacity is 1–100 claims; the rehearsal uses three. This is a finite allowance, not Sybil resistance: someone with many seeds could exhaust a public faucet. The current server binds loopback only; broad public enrollment and stronger admission controls remain separate work.

Public gas transactions retain their exact signed bytes and last valid block height before broadcast. A retry checks canonical historical status and resends the same transaction while valid. Re-signing is allowed only after finalized expiry and another absent historical-status check. Each claim permits at most three gas identities, each with a fee ceiling of 10,000 units; only one successful grant is allowed.

Private grants use normal user-paid native private sends from the faucet reservoir, with a 150,000,000 gross-debit cap per attempt, at most three attempts. Upload journals preserve the original cap. Unknown finalization must resolve canonically before any new proof or upload. The worker writes a durable accepted/failed/expired outcome before clearing a pending identity. Accepted outcomes survive the gap before claim completion; staging rent is recovered before advancing the queue. Refunds do not increase an individual attempt's recorded allowance. The lifetime upper bound on attempted gross debits is capacity × (150,000,000 gas + 30,000 gas fees + 3 × 150,000,000 private-attempt caps), including refundable staging rent. Funding the hot account does not reset these counters.

One worker and one wallet-operation lock serialize reservoir spending. Admission uses a separate short ledger lock, so new claims can queue while a proof runs. The seed must not be used by another wallet process or a copied faucet data directory. Canonical RPC history, the original claim ledger, progress, payment outcomes, pending/staging records and encrypted seed backups are required for recovery; copying only the seed cannot recover distribution limits.

The faucet knows the private-address/public-fee-address association, and public gas transfers expose funding relationships. The wallet explains that relationship before requesting a grant. Test units have no monetary value. HTTPS is required for remote pinned client endpoints; the local rehearsal server itself is deliberately loopback HTTP. There is no automatic mint, refill, bridge or SOL funding.

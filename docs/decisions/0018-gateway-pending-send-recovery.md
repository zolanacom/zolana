# Recover the original pending send through the invited gateway

The existing native client records a signed finalization identity before its first possible broadcast. Gateway acknowledgement loss must recover that original signature and staging record; a lost response is not authorization for another payment. The acceptance uses the same funded desktop seeds, network, grants, HTTPS profile and service identity as LOCAL-021.

The test pauses the signing client only after its pending JSON is complete, then arms a service-owned gate for that exact signature. The gate delegates to the normal invited HTTPS gateway, holds only an authentic successful finalized status for the target, durably records its response hash/slot, and never returns that selected acknowledgement, including on timeout. It does not synthesize a successful transaction or expose a public fault-injection endpoint. The administrator-controlled launchd job temporarily selects `run-ack-test`; the ordinary `run` path uses the unchanged gateway. A service-owned ten-minute session deadline survives validator restarts and parks writers when expired.

A nonce-bound owner-only directory under the system temporary directory coordinates the desktop UID and administrator. Its messages contain only bounded experiment metadata, signatures and journal hashes, not wallet passwords, seed files, source keys or raw RPC capabilities. The administrator verifies actual signature finality and pool/nullifier state through the service UID. The desktop test SIGKILLs its owned signing process while the reply is held, and the administrator then SIGKILLs the owned service supervisor. Launchd replaces the supervisor and both validators. Exact pending/staging hashes and canonical state must survive before the client resolves its original signature over the same HTTPS gateway.

The root controller restores the original normal launchd plist and stops its temporary service in `finally`, including on participant failure. It retains started checkpoints and refuses to launch a replacement experiment against an existing payment record. An administrator process or host crash can interrupt cleanup; the independent service session deadline still limits validator runtime. Original private state is never automatically deleted or reinitialized.

The first live run exposed a verification-helper bug: a fresh checkpoint action queried status before loading its private Unix RPC routes. The gateway had already held the real finalized reply. Failure cleanup terminated the signing client and stopped the service with its original pending/staging journals retained. A separate guarded continuation recovers only that identity, preserving the original failure record and existing gate. It explicitly distinguishes that cleanup from the later injected abrupt supervisor crash. An explicit client-resumed handshake also prevents the controller from overwriting its arm response before the desktop sees it.

Private-send resolution previously scanned from genesis even when an authenticated scan cache was available. Recovery now extends that cache for pending operations without a saved recipient-bound withdrawal receipt, checking its original network, canonical checkpoint header, history continuity and live pool reconciliation. Missing or invalid caches keep the existing complete-history fallback; RPC rollback still fails with the original pending record retained. Recipient-bound withdrawals keep full receipt replay because their recipient/amount receipt map is not in the cache. Resolve returns its scan statistics so real acceptance can verify that it used the authenticated checkpoint. No transaction format, privacy circuit, consensus or fee allowance changes.

After successful resolution and original staging cleanup, a separate fault injection reinstates the exact saved pending JSON to simulate interruption between recording an outcome and durably removing its journal. Resolving that same identity again must leave balances and permanent nullifiers unchanged. This is journal replay without replacement broadcast, not a second payment or a claim that a conflicting proof was submitted.

Tests remain local, with validators paused during coding and after acceptance. Public hosting, remote tester release, seed-only sync at large chain history, recipient-bound withdrawal performance and independent review remain separate work.

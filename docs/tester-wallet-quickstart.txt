ZOLANA (ZOL) TEST WALLET - LOCAL DEVELOPMENT BUILD

Test coins only. This wallet connects to an independent privacy blockchain.
It cannot receive SOL or Solana tokens. There is no Solana bridge or trading.

Requirements: the machine/OS named in MANIFEST.json, Python 3.10 or newer,
and a browser. Rust, a validator, a repository checkout and operator keys
are not required. The current macOS build is unsigned and not notarized;
this archive is for local rehearsal, not an installer ready for distribution.

1. Extract the archive. Verify the archive SHA-256 against a checksum received
   through a trusted channel. A checksum shipped beside an archive does not
   establish its publisher. Preserve upstream/dependency notices.
   A separately prepared signed-release workflow can authenticate downloads
   before execution. Obtain its verifier and publisher/profile pins through an
   independently authenticated channel, then verify/install/run through that
   trusted tool. A verifier or key only supplied with this archive is not an
   independent trust source. This development archive is not an Apple signed
   or notarized release, and start-wallet.command --verify checks hashes only.
2. In Terminal run:
     sh start-wallet.command --verify
     sh start-wallet.command --check
   The second command checks the configured RPC, genesis, native pool and
   withdrawal activation without opening your wallet. For invited profiles it
   checks only genesis; pool/history access needs an admitted, unlocked wallet.
   Loopback profiles need
   a separately running local test network. HTTPS profiles need the configured
   testnet RPC; endpoints and genesis are fixed in wallet-profile.json.
3. Run:
     sh start-wallet.command
   Your browser opens a device-local wallet at http://127.0.0.1:8765/.
   If that port is occupied use --port 8766. The session ends after one hour;
   restart the same command and unlock to resume. Ctrl-C stops the wallet.
4. Create a password and save the encrypted recovery file separately from it.
   Keep both; there is no reset service. You can create/restore while offline;
   balances and payments require the configured network and retained history.

Wallet data lives outside the archive in your user application-data directory,
in the wallet's folder for this chain's genesis hash. --data-dir selects
another owner-only directory. Reuse that directory when updating a bundle.
Never delete an unfinished payment's files or start a replacement payment to
resolve an unknown result. Use Check previous payment, then Recover upload rent.
The launcher refuses to replace a data directory's pinned profile silently.
To update, stop the local wallet, replace only the extracted package, and start
it with the same data directory. Keep that directory and your recovery file.
Check previous payment resolves the original signed payment; it does not send
another payment. It can extend an authenticated checkpoint for private sends.
If the network is offline or behind the verified checkpoint, the original
pending journal stays in place. Retry recovery when the network is healthy.
A new-device restore can fetch verified retained history through the invited
gateway; you do not need an operator history folder. Use the matching updated
wallet/gateway build. Retained data can recover balances but cannot prove an
unknown payment executed or never executed. Recovery tries complete canonical
RPC history when needed; if unavailable, keep the pending file and ask the local
operator for archival RPC recovery. Never send a replacement as a recovery step.

This package has no operator sponsor. Native private-send profiles pay the
reviewed fee from private notes: no public gas balance of your own is needed
for those sends. Review both the amount and private fee before confirming.
Public withdrawals still require a funded public fee account. Legacy send
profiles also use that public fee account, including upfront refundable upload
rent; their review shows its funding shortfall and authorized gross debit cap.
The private recipient receives the reviewed amount.

A configured test-coin endpoint does not guarantee a live funded grant worker.
After saving and confirming your recovery file, use Check test coin grant
(invited profiles) or Request test coins. The returned grant status describes
queued, started, ready or operator-recovery state. Queued is not finalized.
The wallet checks an original queued/started grant for a few minutes; check the
same grant when you return. Grant amounts and whether public gas is included
depend on the selected testnet policy. Native private-only grants do not include
public gas. Restoring your seed reuses the original grant, not a second one.
If invitation access is enabled, the first screen after backup is Join the
private testnet. Enter your operator invitation once to admit this wallet and
queue the same fixed grant. Restoring your seed restores access without another
code; Check existing access can retry a saved admission. Codes/access can expire
or be revoked. Access proofs and codes are credentials: keep them out of URLs,
screenshots and bug reports. Limits survive restarts; wait when a quota is hit.
Profiles without a faucet still require separately provisioned test balances.
Faucet capacity and funds are finite; there is no automatic refill.

The wallet service and browser use your password locally. RPC and, when requested, a signed public faucet claim leave the device.
The seed/password and spending/viewing keys stay in the local wallet. Native
proof generation and payment decryption happen on this device. The invited
gateway knows your membership and receiving address, sees IP/request timing,
and can link submissions to membership. Test grants have no monetary value;
a legacy public-gas grant also reveals a public funding relationship. Remote profiles use
normal certificate-validated HTTPS, no redirects and no proxy auto-discovery.
Local HTTPS profiles may carry a public local test CA. This adds trust only
inside this wallet; certificate expiry and hostname verification remain enabled.
No CA/server private key or raw-RPC operator credential is in the package. If a
certificate expires or verification fails, keep the original wallet and contact
the local operator; do not disable TLS checks.
The RPC/validator consensus is trusted; this is not a light client. Native shielded-send amounts and private counterparties are hidden from the
public ledger. Shared relay payer, fee, timing and nullifiers remain public;
public deposits/withdrawals reveal their amounts and public accounts. This is
not anonymity from the gateway operator or post-quantum security. This prototype is unaudited; physical phone/Safari and remote hosting
have not been accepted. Keep recovery files and passwords out of bug reports.

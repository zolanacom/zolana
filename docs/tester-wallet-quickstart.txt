TEST WALLET - LOCAL DEVELOPMENT BUILD

Test coins only. This wallet connects to an independent privacy blockchain.
It cannot receive SOL or Solana tokens. There is no Solana bridge or trading.

Requirements: the machine/OS named in MANIFEST.json, Python 3.10 or newer,
and a browser. Rust, a validator, a repository checkout and operator keys
are not required. The current macOS build is unsigned and not notarized;
this archive is for local rehearsal, not an installer ready for distribution.

1. Extract the archive. Verify the archive SHA-256 against a checksum received
   through a trusted channel. A checksum shipped beside an archive does not
   establish its publisher. Preserve upstream/dependency notices.
2. In Terminal run:
     sh start-wallet.command --verify
     sh start-wallet.command --check
   The second command checks the configured RPC, genesis, native pool and
   withdrawal activation without opening your wallet. For invited profiles it
   checks only genesis; pool/history access needs an admitted, unlocked wallet.
   Loopback profiles need
   a separately running local test network. HTTPS profiles need the configured
   testnet RPC; endpoints and genesis are fixed in wallet-profile.json.
3. Run:
     sh start-wallet.command
   Your browser opens a device-local wallet at http://127.0.0.1:8765/.
   If that port is occupied use --port 8766. The session ends after one hour;
   restart the same command and unlock to resume. Ctrl-C stops the wallet.
4. Create a password and save the encrypted recovery file separately from it.
   Keep both; there is no reset service. You can create/restore while offline;
   balances and payments require the configured network and retained history.

Wallet data lives outside the archive in your user application-data directory,
under Zolana Test Wallet and this chain's genesis hash. --data-dir selects
another owner-only directory. Reuse that directory when updating a bundle.
Never delete an unfinished payment's files or start a replacement payment to
resolve an unknown result. Use Check previous payment, then Recover upload rent.
The launcher refuses to replace a data directory's pinned profile silently.

This package has no operator sponsor. It receives native private payments,
sends privately and withdraws with user-paid fees after its separate public fee
account has test coins, including upfront refundable upload rent. Send shows
the fee address, public funding shortfall and gross debit cap before you confirm.
Private value is separate from gas; the recipient receives the full amount.
If this profile configures a test faucet, select Get test coins + gas after
saving and confirming your recovery file. One grant supplies 1,000,000 private
test units and 150,000,000 public gas units. The wallet checks finalization
for a few minutes; Check coins + gas resumes the same claim after a restart.
Restoring your seed reuses the original grant; it cannot request a second one.
If invitation access is enabled, the first screen after backup is Join the
private testnet. Enter your operator invitation once to admit this wallet and
queue the same fixed grant. Restoring your seed restores access without another
code; Check existing access can retry a saved admission. Codes/access can expire
or be revoked. Access proofs and codes are credentials: keep them out of URLs,
screenshots and bug reports. Limits survive restarts; wait when a quota is hit.
Profiles without a faucet still require separately provisioned test balances.
Faucet capacity and funds are finite; there is no automatic refill.

The wallet service and browser use your password locally. RPC and, when requested, a signed public faucet claim leave the device.
The seed/password never leave the local wallet. The faucet sees the private
receiving and public fee addresses together. Its test grants have no monetary
value; the public gas transfer reveals a funding relationship. Remote profiles use
normal certificate-validated HTTPS, no redirects and no proxy auto-discovery.
Local HTTPS profiles may carry a public local test CA. This adds trust only
inside this wallet; certificate expiry and hostname verification remain enabled.
No CA/server private key or raw-RPC operator credential is in the package. If a
certificate expires or verification fails, keep the original wallet and contact
the local operator; do not disable TLS checks.
The RPC/validator consensus is trusted; this is not a light client. Shielded
contents are private; public fees, funding/withdrawal amounts and timing are
visible. This prototype is unaudited; physical phone/Safari and remote hosting
have not been accepted. Keep recovery files and passwords out of bug reports.
